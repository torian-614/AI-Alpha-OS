# AI Alpha OS Project Charter

状态：Sprint 0.2 项目章程。后续修改应说明原因并经过 Review。

## 项目第一目标：长期稳定盈利

项目第一目标是长期稳定盈利。研究与工程工作围绕这一目标组织，以可追溯的证据、明确的风险边界和可复现的评估支持决策。

这是项目追求的长期目标，不是已实现的结果或收益承诺。当前没有交易系统、盈利记录或可验证的策略表现。评价周期、风险约束和验收阈值由后续 PRD 与评审明确，本章程不设定未经验证的数值。

## 非黑箱原则

- 记录每个 Alpha 的来源、假设、输入、适用条件与失效条件。
- 重要结果能追溯至数据版本、配置、实验过程和评审记录。
- 涉及模型或 Agent 的后续任务必须说明职责、输入输出边界、评价依据与已知局限；不能解释或复现的部分必须显式记录。
- 研究结论、排名和自动化建议均不直接构成交易或上线授权。
- 保留失败实验、否决理由和退役记录，不能只展示成功结果。

## 开源透明原则

- 在授权范围内公开工程结构、设计理由、研究方法、评估口径和变更历史。
- 通过 RFC、PRD、ADR、Review 和 Git 记录，使重要改变可审查。
- 清晰区分计划、已实现能力和已验证结果，提供可复现所需的说明。
- 不公开凭据、个人信息、受限数据或未获得再分发许可的内容；受限依赖须说明获取条件与复现限制。
- 开源许可证尚待维护者选择；本章程不替代 LICENSE，也不变更仓库可见性或授予许可证。

## Alpha 生命周期管理

Alpha 指待验证或已评估的收益来源假设。每个 Alpha 使用稳定标识，阶段转换保存版本、证据、日期、审查者及理由。

| 阶段 | 主要记录位置 | 转换条件 |
| --- | --- | --- |
| 提出 | research/alpha/ | 明确来源、假设、边界及评价计划 |
| 研究 | research/factors/、research/strategies/、research/experiments/ | 形成可复现的研究记录，列明负面结果与局限 |
| 评估 | backtest/、arena/ | 按事先约定的规则记录评估证据与比较限制 |
| 决策 | decision/ | 审查证据，明确接受、退回或否决及理由 |
| 监测 | decision/ 中关联的后续记录 | 仅在另行授权实施后监测，按预定条件复审 |
| 暂停或退役 | decision/、research/reports/ | 记录失效、停止原因和影响，保留完整历史 |

以上是管理流程，不代表各阶段能力已经实现。评估不通过可退回研究或归档；重新启用已暂停或退役的 Alpha 必须形成新版本与新评审，不覆盖历史。监测、上线和任何交易执行均需独立任务与授权。

# AI Alpha OS 网页展示与源码分享设计

## 目标

为 AI Alpha OS 提供一个无需登录、知道链接即可访问的公开演示网页，同时让访客能够从网页进入公开 GitHub 仓库查看 Python 量化管线与网页源码。

首版兼顾系统介绍与可操作体验，但仅使用固定模拟数据。它不连接证券账户、不自动下单、不读取本地数据库、不请求 API Key，也不提供投资建议。

## 受众与成功标准

主要受众是希望快速理解和体验 AI Alpha OS 的非开发者朋友。开发者也应能从页面进入仓库，复现演示计算并理解各模块的关系。

交付完成需要同时满足以下条件：

- 公开演示链接无需登录即可打开。
- 桌面和手机布局均可阅读和操作。
- 首页清楚说明产品定位、当前能力和研究模拟边界。
- 互动实验室提供趋势向上、震荡观察、数据质量异常三个固定场景。
- 调整因子权重后，Alpha 分数、风险状态和研究决策即时更新。
- 网页默认结果与 Python 管线生成的黄金样本一致。
- 页面提供公开 GitHub 仓库入口，仓库 README 提供在线演示入口和运行说明。
- 发布内容不包含密钥、账户信息、本地路径、数据库、缓存或个人数据。

## 信息架构

网页使用单页结构，包含以下四个区域：

1. **首页概览**：一句话定位、研究模式标识、当前能力和显著的模拟研究声明。
2. **决策链路**：展示固定 OHLCV 数据经过标准化、质量检查、因子计算、Alpha 评分、风险闸门和决策记录的顺序。
3. **互动实验室**：选择预置场景、调整趋势/动量/成交量权重、查看结果和解释。
4. **源码入口**：链接到公开 GitHub 仓库，并说明如何运行 Python 管线和网页。

## 视觉方向

采用深色量化终端风：深蓝黑背景、蓝色数据层级、绿色通过状态、黄色观察状态、红色阻断状态。界面保持专业和高信息密度，但避免仿真实盘交易终端，不展示买卖按钮、收益承诺或账户资产。

桌面端使用双栏结果布局；移动端按输入、分数、风控、决策的顺序折叠为单栏。核心文字和状态不依赖颜色单独传达，状态同时显示标签与原因码。

## 组件与职责

网页作为仓库中的独立 `web-demo/` 模块，使用纯静态 HTML、CSS 和 JavaScript：

- `index.html`：语义结构、页面内容和无脚本时仍可阅读的系统说明。
- `styles.css`：响应式布局、终端视觉主题和可访问状态样式。
- `demo-data.js`：三个固定、匿名化的 OHLCV 场景及其元数据。
- `alpha-engine.js`：与 Python 基线一致的趋势、动量、成交量因子和加权分数组合。
- `decision-engine.js`：风险状态、阈值判断、原因码和 Decision Record 生成。
- `app.js`：界面状态、权重调整、渲染、重置和错误提示。
- `tests/`：黄金样本、计算边界和异常输入测试。

各模块只通过明确的数据对象通信。演示引擎不访问网络，不读取浏览器持久化数据，也不写入用户信息。

## 数据与交互流程

用户先选择三个场景之一。页面读取对应的固定 OHLCV 样本，并依次执行：

`固定样本 → 因子分数 → 权重归一化 → Alpha Score → 风险闸门 → 研究决策 → Decision Record`

三个可调权重分别对应趋势、动量和成交量。任何非负组合都先按总和归一化；若总和为零或输入无效，页面恢复默认权重 `0.40 / 0.35 / 0.25`，并显示解释性错误提示。

默认阈值与 `configs/decision_mvp.json` 保持一致：

- Alpha Score 低于 50：`REJECT`
- Alpha Score 大于等于 50 且低于 70：`WATCH`
- Alpha Score 大于等于 70：`CANDIDATE`
- 风险状态为 `BLOCK`：无条件 `REJECT`

结果区展示总分、三个因子分数、归一化权重、风险状态、风险标记、研究决策、置信度、原因码、策略版本、配置版本和模拟 Decision Record JSON。每个因子提供当前公式和窗口说明。

## 错误处理与降级

- JavaScript 未加载时，产品介绍、系统链路、风险声明和源码入口仍可阅读。
- 样本数据不足时，因子返回不可用状态，风险闸门产生 `INSUFFICIENT_HISTORY`，最终决策为 `REJECT`。
- 数据字段缺失、OHLC 无效、成交量无效或重复记录时，风险闸门显示具体风险标记并阻断决策。
- 权重输入无效时恢复默认配置，不保留错误状态继续计算。
- 所有异常均在页面内解释，不弹出不可恢复的浏览器对话框。

## 测试策略

Python 管线先对三个固定场景生成黄金结果。网页测试读取相同的输入和预期输出，验证因子分数、权重归一化、Alpha Score、风险状态、原因码和最终决策。

测试还覆盖：

- 阈值 50 和 70 的边界行为。
- 权重为零、负数、非数字和总和不为 1 的情况。
- 数据不足、字段缺失、重复记录和无效 OHLCV。
- 重置操作与场景切换。
- 窄屏布局、键盘操作、焦点可见性和状态文字可读性。

## 发布与源码交付

网页代码与现有 Python 项目一同保存在 AI Alpha OS 仓库中。仓库 README 顶部增加在线演示入口，网页提供 GitHub 源码入口。

当前本地工作区包含未提交的 Sprint 2.0 修改，并且本地 `main` 落后远端。实施阶段先完整记录现状，在隔离分支中同步远端并整合网页，避免覆盖或丢失已有修改。只有在测试通过和发布内容扫描完成后，才推送网页与相关文档。

网页使用静态托管发布为公开链接。构建不包含运行时密钥、真实行情请求或后端服务。发布前检查 Git 跟踪文件、演示样本、构建产物和文档中的敏感内容。

## 非目标

首版不包含实时行情、真实账户、自动交易、用户登录、数据库、服务器端 Python 执行、回测平台、组合管理、自定义策略脚本或收益预测。后续若需要其中任何能力，应单独设计和评审。

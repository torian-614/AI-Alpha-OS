# AI Alpha OS 回测系统规则

状态：V1 设计规范；无引擎实现、无已执行回测。目标是在冻结数据、规则和参数条件下，复现历史信号、模拟成交及结果反馈。

## 一、范围与运行清单

V1 基线采用 A股现货、现金账户、只做多、不融资融券、不做空的模拟模式。只在已核实交易规则与数据覆盖的股票池内运行，不因证券身份支持多个交易所就默认已支持全部板块。

每次运行保存 run_id、样本区间、历史股票池版本、初始资金、数据快照、特征与规则版本、参数版本、交易日历及市场规则版本、手续费版本、滑点版本、撮合模式、估值频率与结果文件引用。当前不指定参数数值；缺少必要配置应拒绝启动，不能默认为零成本。

市场制度依据交易所、板块、证券状态及历史生效区间配置，不能对所有 A股统一硬编码涨跌幅或申报数量，也不能把今天的规则用于全部历史。上交所规则通知明确新规则的施行日期及部分条款暂缓安排，说明历史回放需保留版本依据。[上交所规则发布通知](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)

## 二、时间与信息约束

- 数据遵循 [DATA_CONTRACT.md](../data/DATA_CONTRACT.md)；历史模式按 available_at 截断，实时模拟按 available_at 与 ingested_at 的较晚值截断。
- bar 收盘形成信号后，最早在之后的可交易窗口成交，不允许拿完整当日 K 线作决定再按当日开盘价成交。
- 竞价 final 数据形成的信号不能参与已经结束的同次集合竞价，V1 在随后连续竞价窗口尝试成交。
- 当需要竞价或盘中证据却只有日线时，该实验标为数据不足，不得插值或捏造竞价数据。
- 为保持确定性，同一时点事件按照市场数据、已知信息更新、信号、风控和订单的固定顺序处理，并保存顺序版本。

## 三、买入规则

1. 使用 [Alpha 评分框架](../alpha/ALPHA_SCORING.md) 的当时结果，满足冻结的入选与触发条件；本规范不设置具体分数阈值。
2. 为每个信号生成 decision_id，记录输入、规则、评分和时间，即使订单未成交也保留。
3. 下单前检查股票池、证券状态、交易时段、申报数量和报价合法性、可用现金、持仓与板块风险上限。
4. 冻结的仓位规则给出目标数量，按照历史有效最小申报量与步长取合法数量；现金须覆盖价格和预计费用。
5. V1 基线不对同一证券未结束的持仓周期主动加仓；多信号竞争现金时按 final_score 降序、security_id 升序处理，规则在运行前固定。
6. 订单状态与成交状态分开保存，未满足可交易条件记为 rejected、unfilled 或 expired，并说明原因。

## 四、卖出规则

退出触发类型包括规则失效、风险退出、持有期到期、止损与止盈。具体阈值、持有期和启用组合由 parameter_version 固定，不在此确定盈利参数。

- 只允许卖出可售持仓数量，不得超卖。V1 普通 A股模拟按 T+1 可售限制建模，当日买入不作当日卖出；节假日按交易日历推进。交易所对回转交易设有品种边界，特殊品种不套用本基线。[深交所交易规则，第 3.1.4—3.1.5 条](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)
- 同时触发多个退出条件时，基线顺序为风险退出、止损、持有期到期、规则失效、止盈；记录全部触发原因，只生成一个退出请求，避免重复卖出。
- 退出信号不等于成交。停牌、无流动性或价格限制导致不可成交时继续持仓，记录风险暴露与延迟，不按触发价假设卖出。
- 信号由已完成 bar 判断时，于下一可交易 bar 尝试执行；因此止损价格不是保证成交价格。
- 期末未平仓头寸保留并按统一估值口径纳入净值，不强制按不可能成交的收盘价清仓，不纳入已闭合交易胜率。

## 五、成交模拟

### V1 基线：下一完整 bar 模式

该模式是研究用近似，不是对交易所排队的精确重建。

- 订单在 signal_time 之后且 bar_start 不早于订单可提交时间的下一完整可交易 bar 尝试执行。参考价为该 bar 的 open，成交价加入不利滑点并按价格最小变动单位处理。
- 撮合结算在该 bar 完成之后确认；该 bar 的成交量只能用于事后限制模拟成交容量，不能作为开盘时已知特征。成交记录同时保存参考时点与确认时点。
- 成交数量不超过请求数量、可买/可售数量及该 bar 成交量乘参与率的下取整值，且需满足适用数量规则。参与率须预先配置，未配置不能无限量成交。
- 合法滑点价必须在 bar 价格区间和适用涨跌停边界内；否则该 bar 不成交，不把价格裁剪到有利位置。报价买入向上、卖出向下取合法 tick。
- 部分成交允许，剩余数量在后续符合条件的 bar 按同一规则尝试；当日结束撤销未成交部分，次日需要根据仍有效的规则新建并关联订单。
- 没有成交、停牌、报价或规则缺失时不成交。无排队数据时，基线保守拒绝触及涨停价的买入与触及跌停价的卖出尝试，并记录原因，不凭 high/low 触价推断排队成功。
- 分钟模式与日线模式须独立报告。日线无法验证盘中顺序，不用于宣称竞价或盘中精确成交。

### 竞价及更精细撮合

V1 基线不模拟集合竞价排队。未来若增加竞价成交模式，须有截止前可用输入、有效申报证据与匹配量约束。交易所采用价格和时间优先，集合竞价以统一成交价格撮合；仅有 OHLC 或虚拟匹配量不能证明某笔委托成交。[深交所交易规则，第 3.4.2—3.4.3 条](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)

若未来支持 bar 内止损/止盈触价，同 bar 多条件先后无法判定时应使用更细数据或事先冻结的保守规则，不得事后选择有利路径。

## 六、手续费

按历史有效期和交易方向读取费率配置，逐笔记录成交金额与费用分项：

成交金额 = 成交价 × 成交股数

总费用 = 券商佣金 + 适用交易税费 + 适用过户及其他费用

- 每项明确计费基数、方向、费率、最低收费、取整方式、有效期与依据。
- 佣金是否包含其他费用必须记录，防止重复计费；最低佣金按配置的订单或结算单位累计，部分成交不能无条件重复收取最低值。
- 买入现金流为成交金额与费用之和的负值；卖出现金流为成交金额扣除费用。
- 费率属于市场与账户条件，按历史依据配置，不为提高回测结果而优化。本设计不写死当前费率。
- 对净收益、回撤及胜率均使用扣除适用费用后的账本结果。

## 七、滑点

基线使用预先配置的非负比例 s：

买入模拟价 = 参考价 × (1 + s)

卖出模拟价 = 参考价 × (1 - s)

再执行 tick 与价格合法性检查。s 应小于 1，具体值及流动性分层方式待确定。滑点已体现在成交价中，不再从收益重复扣除一笔相同损失。

滑点用于保守成本建模和敏感性分析，不作为制造收益的可优化变量。零滑点仅可用于明确标识的对照实验，不作为缺失配置的默认值。

## 八、资金账本、收益与权益事件

- 初始资金 E_0 > 0；基线运行不允许外部入金或出金。
- 净值 E_t = 现金余额 + 持仓按当时价格计值 + 已确认但未到账权益；冻结资金只是现金可用性变化，不重复扣减资产。
- 总收益率 = E_T / E_0 - 1；注明评价区间及估值频率，不把累计收益当作年化收益。
- 基线日终估值使用不复权收盘价；停牌使用最近有效价格并标记 stale，报告估值陈旧程度，不把缺失价格记为零。
- 分红、送转等通过现金、应收权益和持仓数量入账；不得既使用复权价格计净值又重复记权益收益。
- 若持仓跨越未支持权益事件、缺失事件或退市结算而无法可靠估值，停止该运行并报告不完整结果，不以最后价格永久冻结来掩盖损失。

## 九、最大回撤计算

基线使用含费用与未实现盈亏的日终账户净值，包含初始净值点：

H_t = max(E_0, E_1, …, E_t)

D_t = (H_t - E_t) / H_t

MDD = max(D_t)

输出为非负比例，同时保存峰值日期、谷值日期及恢复日期（尚未恢复则为空）。日终最大回撤不等于盘中最大回撤；若采用分钟净值须单独标记频率，不能混比。非正初始资金或净值缺失使正式统计无效。

人工核对示例（合成数据）：净值 100、120、90、110，最大回撤为 (120 - 90) / 120 = 25%。该示例不是实际回测结果。

## 十、胜率计算

一笔完整交易定义为同一证券从零持仓开始到再次零持仓结束的持仓周期；部分买入与卖出归入同一周期，周期未结束不计胜率。费用按账本分配，权益收益按归属计入。

已闭合周期净损益 = 卖出收入 - 买入支出 - 全部适用费用 + 归属权益收益

胜率 = 净损益大于 0 的已闭合周期数 / 全部已闭合周期数

盈亏为零计入分母、不计入盈利笔数；净损益使用冻结的金额精度判定。没有已闭合周期时胜率为 null，并注明 no_closed_trades。未成交信号不算亏损交易，另报信号数、成交率、未成交原因和未平仓数。

人工核对示例（合成数据）：四个已闭合周期净损益为 10、-5、0、3，胜率为 2 / 4 = 50%。

## 十一、输出与可追溯性

保存 decision_id → order_id → fill_id → position_cycle_id 的关联，以及 run_id、时间、security_id、输入引用、触发规则、原始评分、价格、数量、费用、状态与原因。

结果至少包含净值序列、总收益、最大回撤、胜率及分母、已闭合周期数、未平仓与未成交统计、数据覆盖和限制说明。每次决策的最终结果以追加记录关联，不能覆盖原始输入或提前写入收益。

## 十二、后续实现验收场景

未来实现须验证：未来数据被拒绝、final 竞价信号不能回填竞价成交、同日新买头寸不可售、停牌与涨跌停成交限制、数量和现金约束、部分成交费用、滑点不重复扣除、复权与权益不重复计入、无闭合交易胜率为 null，以及上述最大回撤和胜率人工示例。
